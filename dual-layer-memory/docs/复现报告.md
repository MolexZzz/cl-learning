# 复现报告：Dual-Layer Agentic Memory

> 论文：*Dual-Layer Agentic Memory with Fast Write Routing and Slow Consolidation*
> （arXiv:2608.22215v2，Li et al., 2026）

本仓库已按论文实现完整实验框架，并**移除了模拟后端**：所有实验只调用真实
Qwen3-1.7B/8B（或 smoke 配置里的 0.6B/1.7B）和真实 ZsRE 数据。代码在 CPU 上
通过了单元测试，但论文规模的完整运行需要在 CUDA 机器上执行。

---

## 1. 现在拿到 GPU 能直接跑吗？

**基本可以，但需要三步准备，且不应期待一次就复现论文的精确数字。**

### 必须满足

1. **CUDA 节点**：论文用 4×H20（96GB）。8B bf16 权重约 16GB，1.7B 约 3.4GB，
   两个同时加载约 20GB；单卡 80GB 也能跑，但速度慢。Mac/MPS 不适合 8B。
2. **ZsRE 数据**：论文的 201,352 事实 / 6,040,560 probes 版本**尚未公开**
   （作者说接收后释放）。公开常见的 ZsRE 版本约 15 万条问题、每条事实的改写
   数量也远少于 30；仓库支持常见 ZsRE 格式，但换一份 dump，绝对数字一定会变。
   见 `docs/ALIGNMENT.md` §1。
3. **依赖**：PyTorch ≥ 2.2、Transformers ≥ 4.51、PEFT ≥ 0.14。先跑
   `python scripts/check_gpu.py`，确认能加载模型、提特征、生成一次。

### 推荐流程

```bash
pip install -e ".[dev,analysis]" && pip install -r requirements-gpu.txt
python scripts/prepare_zsre.py --input /path/to/zsre --out data/zsre

# 1) 500 条事实的 pilot，先验证标签分布和 No/Full Store
CONFIG=configs/paper_full.yaml
python -m dlmem.cli prepare  --config $CONFIG --set run_name=pilot \
  --set data.max_facts=500 --set eval.episodes=1 --set eval.facts_per_episode=20 --set eval.turns=100
python -m dlmem.cli train    --config $CONFIG --set run_name=pilot
python -m dlmem.cli evaluate --config $CONFIG --set run_name=pilot

# 2) 全量（预计单节点 2–4 天，标注占大头）
bash scripts/run_full.sh configs/paper_full.yaml
```

### 时间与显存

- 行为标注：6,040,560 probes × 2 次生成 = **12.08M 次 8B 生成**，4×H20 上约
  10–20 小时（取决于 batch/利用率）。
- 特征：201k facts × 2 个模型，约 1–3 小时。
- 流式评测：9 个策略 × 300×400 次查询 ≈ 1M 次 8B 生成。
- 写回 SFT：约 7 万条样本 × 3 epoch，单卡 LoRA 数小时到十几小时。
- 固化后还要对测试集（可选训练集）重新标注，再花一遍标注时间。
- 总计约 **2–4 天**（4×H20）。先用 pilot 外推。

显存不够时：降 `model.prompt_batch_size` / `generate_batch_size` /
`eval.batch_episodes`，或 `model.quantize_4bit: true`（bitsandbytes，Linux/CUDA）。

## 2. 为什么之前的复现结果与论文不对齐？

之前的结果来自模拟后端，**它本来就不可能对齐**：哈希嵌入、状态相关的 NLL、
按潜变量生成答案，只能验证代码路径。现在模拟后端已删除。即使换成真实 Qwen3，
仍会有以下偏差来源（按影响从大到小）：

| 来源 | 具体问题 | 影响 |
|---|---|---|
| **数据** | 论文 201k/30-probe 的 ZsRE 版本未公开；不同 dump 的事实数、改写难度、答案别名都不同 | 最大，直接改变 38%/88% 两个锚点 |
| **模型/提示** | Qwen3 base/instruct、thinking 开关、答案格式、`max_new_tokens`、截断 | No Store EM、拒答率、标签 |
| **标签规则** | EM 归一化（包含 vs 严格）、拒答正则、`rho/gamma` 边界 | 写入率 76.5% 与标签分布 |
| **检索** | 论文未指定检索器；本仓库用 BM25 top-3 | Full Store EM、上下文噪声 |
| **路由器** | 奖励目标、λs/λe、门控监督划分、升级预算、校准 | 存储–EM 工作点（如 65%/77%） |
| **流式协议** | Algorithm 1 对“注入轮是否也提问”有歧义；本仓库用 T−K 个查询轮 | 指标轻微变化 |
| **写回 SFT** | LoRA rank/LR/epoch、样本构造、驱逐阈值、重标注范围未给出 | SFT 后 No Store（69%）最敏感 |
| **指标口径** | SFT 后 store 指标用静态标签还是新标签；拒答定义 | 表 1 个别列 |
| **随机性** | GPU kernel、batch、device_map 分片 | 单次运行可差 0.1–1 个点 |

详细的排查顺序见 `docs/ALIGNMENT.md`。**先对齐 No Store≈38.0% 和
Full Store≈87.8%，再谈路由器**；如果 Full Store 低，问题在检索/QA/标签，不在
路由器。

## 3. 这次为 GPU 运行做的修改

1. **删除模拟后端**：`models/mock.py`、`data/synthetic.py` 及所有相关配置、
   测试、结果图全部移除；配置里不再有 `model.backend` / `data.source`。
2. **显存安全**：特征提取的 token NLL 改为按位置分块计算，避免把
   `B×L×151k` 的 logits 整体转 fp32；8B 的 prompt batch 默认 16。
3. **设备处理**：`device_map: auto` 分片时输入张量放到实际首层设备；单卡可设
   `device_map: null`。
4. **长度分离**：`feature_max_length`（默认 256）与 `qa_max_length`（默认 768）
   分开；后者要容纳 top-3 记忆 + 指令 + 问题。
5. **SFT 增强**：gradient checkpointing、`use_cache=False`、chat template
   `enable_thinking=False`、保存 adapter、释放显存。
6. **配置校验**：必须提供 `data.zsre_path` 或 `data.hf_name`；非法 loss/
   supervision/calibration 直接报错。
7. **GPU 预检**：`scripts/check_gpu.py` 加载真实模型、提特征、生成一次。
8. **真实模型 smoke 配置**：`configs/gpu_smoke.yaml`（0.6B/1.7B，400 事实），
   用于在新机器上几分钟验证全链路，不含任何模拟。
9. **测试**：24 个 CPU 单元测试通过；真实模型测试需
   `DLMEM_HF_MODEL=... pytest tests/test_hf_integration.py`（默认跳过，绝不
   伪造模型行为）。
